PlotJuggler layout

~15 min, once per base

Build one four-pane layout, save it, and reuse it for every test and every future MCU.

How to read a number in PlotJuggler
  • Mean, σ, min, max: zoom to the steady part, then right-click → Statistics (visible range).
  • A single value or a time: drag the time slider; the legend shows each series at the tracker.
  • Angle from a rate: Apply filter → Integral on an ω series.
  • Message gaps: custom series (f(x)) on any /joint_states field, Lua: if prev then d=time-prev end prev=time return d or 0.
  • Wheel target for an MCU without introspection: custom series on cmd_vel_out linear x, with v1 = angular z: return (value - v1*0.125)/0.0308*159.15 (left, mrps; + for right).

R1

PID tuning

only if T1 or T3 fail

Change one gain at a time, rerun T1, and fill one row per gain set. Pick the knee, not the extreme.

pid() {  # pid KP KI [KD], x1000 units (1500 = 1.5), both wheels
  ros2 topic pub -t 3 /kestrel_tuning_controller/commands \
    control_msgs/msg/DynamicInterfaceGroupValues \
    "{interface_groups: [kestrel_pid], interface_values: [{interface_names:
      [kp_l, ki_l, kd_l, kp_r, ki_r, kd_r], values: [$1, $2, ${3:-0}, $1, $2, ${3:-0}]}]}"
}
pid 1500.0 3000.0
#kpkiOvershoot %Settling ms|Steady err| %Ripple %L−R %Low-speed err %

Kestrel sweep for reference: kp 1 / ki 2 → 6.0 % overshoot, 3.1 % error, 6.7 % low-speed. kp 1.5 / ki 3 → 5.4 %, 1.7 %, 3.9 %.

Read overshoot on the firmware velocity's 200 ms average, against the ramped target. One tick in the MCU's 100 ms window is about 3.7 % at 0.1 m/s, so raw samples are mostly quantization.

R3

Nav2 and SLAM settings

derived from your numbers
Rotation floor (T3)—DWB min_speed_theta, rotation shim rotate_to_heading_angular_vel and spin behaviour all stay at or above this.
Outer-wheel cap at 90 % duty (T4)—Keep v + 0.125·|ω| at or below this.
Twist scale (T1)—MPPI and DWB seed predictions with this twist.

All controllers

  • Velocity smoother = diff_drive limits or lower: 0.35 m/s, 1.5 rad/s; 0.5 / −0.8 m/s²; 2.0 / −3.0 rad/s².
  • Smoother feedback OPEN_LOOP unless T8 is clean.
  • Yaw goal tolerance wide enough that the last correction never asks for a turn below the floor.

MPPI

  • vx_max, wz_max under the cap; model_dt = controller period.
  • Most sensitive to twist scale and latency: a biased ω shows up as wobble on straight paths.
  • It asks for slow rotations freely. With a floor, pair it with the rotation shim.

DWB

  • acc_lim_*, decel_lim_* = the base limits.
  • min_speed_theta ≥ the floor; max_vel_x, max_vel_theta under the cap.

Rotation shim

  • rotate_to_heading_angular_vel between the floor and 1.5 rad/s (check its default against that).
  • max_angular_accel ≤ 2.0 rad/s².
  • Expect small costmap shifts after long spins (T6 scrub).

SLAM (slam_toolbox)

  • Needs T6 and T7 green: heading drift bends maps, scale error stretches them.
  • odom → base_footprint continuous, at least as fast as /scan (10 Hz).
  • First map slowly: ≤ 0.2 m/s, turns between the floor and 1 rad/s.

AMCL

  • T2 distance and T6 heading errors say how far alpha1–4 can drop from the defaults.
